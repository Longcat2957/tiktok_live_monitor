# 백엔드 안정화 계획 및 검증 기준

## 범위
단일 프로세스·단일 계정·댓글 전용·메모리 상태를 유지한다. DB, Redis, 별도 서비스는 추가하지 않는다.
기존 UI 기능을 유지하고 API 변경을 프론트엔드와 함께 적용한다.

## 구현 순서
1. 세션 관리자 도입: 수신/소비/감시 태스크를 이름으로 소유하고 세션 전환을 직렬화한다.
   요청 연결이 끊겨도 시작한 전환은 완료한다. 이전 세션의 늦은 이벤트는 폐기한다.
2. 종료 안전성: TikTok 정리 중 취소를 삼키지 않는다. 정리는 제한 시간 내 수행한다.
   종료되지 않는 작업은 격리하고 새 수신을 막으며 health 503으로 알린다.
3. 송신 공정성: 소비 루프가 송신 태스크에 실행 기회를 준다.
   빠른 브라우저는 순간 배치를 순서대로 받고 느린 브라우저만 독립적으로 끊는다.
4. API 분리 및 충돌 방지:
   - POST /account: 대기 상태에서 시작
   - POST /refresh: 현재 모드·계정 재연결
   - PATCH /config: 현재 모드에서 허용된 설정만 부분 변경
   - DELETE /account: 종료
   모든 변경은 session_id를 필수로 받아 잠금 안에서 확인하고 불일치 시 409를 반환한다.
5. 로컬 접근 검증: HTTP Host 제한, 변경 요청 Origin 검사, WS Origin 필수 검사.
   프론트엔드 개발 프록시는 원래 Host/Origin을 보존한다.
6. 장애 감시: 수신/소비 태스크의 비정상 종료 시 오류 상태를 알리고 제한된 지수 간격으로 복구한다.
   방송 미시작은 정상 대기다. 내부 장애는 health 503으로 구분한다.
7. 자원 및 로그: 댓글·이름 길이, 연결 수, 대기 명령 수를 제한한다.
   DEBUG 설정은 앱 로거에만 적용하고 외부 예외의 본문·payload는 로그에 출력하지 않는다.
8. 회귀 테스트: 취소 타이밍, 늦은 콜백, 순간 배치/느린 클라이언트, 동시 요청,
   오래된 설정창, 작업 실패·복구, 출처 거부, 실제 HTTP/WS 및 프록시 경로를 검증한다.

## 완료 기준
- pytest/mypy/ruff 및 frontend check/test/build/E2E 통과.
- mock으로 재현 가능하고 TikTok 자격 증명·실방송에 의존하지 않는다.
- 동시 변경 중 한 요청만 성공하고 나머지는 409, 검증·충돌로 거절된 요청은 상태를 변경하지 않는다.
- 정상 브라우저에 101개 이상 순간 배치가 와도 오판으로 끊지 않는다.
- UI에서 설정·재연결은 계정을 바꾸거나 종료된 방송을 다시 시작하지 않는다.
- 운영 문서에 API, 상태·복구, 메모리/과부하 한계와 배포 검증 범위를 기록한다.

## 운영상 한계
Python 태스크 취소는 협력적이다. 외부 라이브러리가 종료를 거부하면 격리 후 새 연결을 차단한다.
health 503만으로 Docker가 컨테이너를 재시작하지는 않으므로 이 상태는 명시적인 재시작 대상이다.
실제 TikTok 서비스와 Raspberry Pi의 장시간 검증은 로컬 mock 테스트와 구분해 보고한다.


## 구현 및 검증 결과 (2026-09-15)

계획 1–8을 구현했다. 세션 전환은 `app/session.py`, 이벤트 경계는 `sources/base.py`,
송신은 `websocket.py`, API·출처 검사는 `main.py`가 담당한다.
프론트엔드와 Vite 프록시도 분리된 API 및 session_id 계약으로 함께 전환했다.

- Backend: pytest **35개**, mypy, ruff 통과.
- Frontend: check 오류/경고 0, 단위 테스트 **13개**, production build 통과.
- Browser: E2E **9개** 통과. 오래된 설정창의 재시작 차단 및 별도 Vite 개발 서버 경로 포함.
- 실제 Uvicorn HTTP/WebSocket에서 2개 브라우저에 500개 댓글 순서 전달,
  출처 거부, 동시 변경 200/409, 작업 정리를 검증했다.
- Docker 이미지 빌드와 별도 검증용 컨테이너의 UID 10001, 읽기 전용 파일시스템,
  localhost 포트, static UI, mock WS, 설정/재연결/충돌/종료를 확인했다.
- 실행 중인 mock 수신이 있는 상태에서 SIGTERM 종료 후
  `Application shutdown complete` 및 `Finished server process` 로그를 확인했다.
  해당 Uvicorn은 SIGTERM을 다시 전달해 종료 코드 143을 반환하며 강제 종료(137)는 아니었다.
- Compose 구성은 .env.example을 사용해 검증했다. 사용자의 .env를 생성하거나 수정하지 않았다.
- 테스트용 컨테이너·임시 Vite 서버는 종료했다. 기존 실행 서비스에 배포하지 않았다.
- 의존성 버전은 유지했다. 이미 사용하던 httpx를 직접 런타임 의존성으로 명시하고 uv.lock을 갱신했다.

### 남은 외부 검증

실제 TikTok 방송, Raspberry Pi/ARM64 이미지 실행, 장시간 부하·네트워크 장애 실험은 이 검증에 포함하지 않았다.
기존 Starlette/httpx 및 TikTokLive/websockets의 deprecation 경고는 남아 있다.
외부 라이브러리가 협력적 종료를 거부하는 상황은 안전하게 격리하지만 자동으로 강제 종료하지 않는다.
`shutdown_timeout` 발생 시 컨테이너를 재시작해야 한다.
